# Архитектура проекта

## Общая схема:

```
Пользователь → React Router → Страница (Page)
                            ↓
                        Компоненты (Card, Header...)
                            ↓
                        Хуки / Контекст / Redux
                            ↓
                        API / localStorage
```

## Поток данных:

### 1. Инициализация приложения

- При монтировании компонента `App` запускается `useEffect`.
- Выполняется `fetch` к эндпоинту `http://noxer-test.ru/webapp/api/products/on_main`.
- При успешном ответе:
    - Товары (`products`) сохраняются в Redux как `cards`
    - Категории (`categories`) — как `types`
    - Подсказки поиска — в локальное состояние `fastSearchStrings`
- При ошибке сети:
    - Автоматически загружается резервный файл `public/data.json`
    - Данные из него также сохраняются в Redux

### 2. Управление пользовательским состоянием

- **Профиль**:  
    Данные (`email`, `password`) хранятся в `localStorage` и синхронизируются с состоянием `person` через `useState`.
- **Тема**:  
    Используется хук `useDarkTheme`, который:
        - Читает/сохраняет значение в `localStorage`
        - Добавляет/удаляет класс `dark-theme` на `<body>`
- **Поиск**:  
    Управляется через контекст `SearchContext`:
    - `isSearchActive` — показывает/скрывает панель поиска
        - `searchQuery` — текущее значение поиска
        - Состояние доступно глобально через `useSearch()`

### 3. Работа с товарами
- Все компоненты получают данные через хук `useCardsDatas()`, который:
    - Извлекает `cards`, `likedItems`, `basketItems` из Redux
    - Вычисляет производные: `likedCards`, `basketCards`
- Изменения происходят только через `dispatch`:
    - `LIKE_ITEM` — переключает избранное
    - `ADD_TO_BASKET` / `SET_BASKET_ITEM_COUNT` — управляет корзиной

### 4. Рендеринг
- Все компоненты — чистые функции без побочных эффектов
- Состояние обновляется иммутабельно (создаются новые объекты в редьюсере)
- UI реагирует на изменения через React-перерисовку
